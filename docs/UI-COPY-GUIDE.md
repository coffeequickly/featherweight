# UI 문구·번역 작성 기준

작성일: 2026-09-09. 한국어와 영어 UI에 함께 적용한다.

## 목적

사용자가 현재 상태를 이해하고 필요한 행동을 선택할 수 있도록 쓴다. 코드의 변수명이나 개발자의 판단 과정을 그대로 화면에 옮기지 않는다. 번역은 같은 사실과 행동을 전달하되, 언어별로 자연스러운 문장 구조를 사용한다.

## 문구의 역할을 먼저 정한다

| 역할 | 작성 방식 | 예시 |
| --- | --- | --- |
| 화면 제목 | 무엇을 확인하거나 조작하는지 표현 | 저장된 폰트 / Saved fonts |
| 상태명 | 짧은 명사구, 문장 마침표 생략 | 저장 공간 부족 / Insufficient storage |
| 버튼 | 실행할 동작을 구체적으로 표현 | 다시 저장 / Retry save |
| 안내 | 완전한 문장으로 이유 또는 방법 설명 | 개별 파일 대신 폴더를 선택하세요. |
| 오류 | 확인된 문제 → 필요한 행동 | 파일을 읽지 못했습니다. 다른 폰트 파일을 선택하세요. |
| 상세 정보 | 버전·파일명·오류 원문 등 진단 근거 | 상세 오류: HTTP 404 |

상태명의 ‘저장 실패’는 적절하다. 긴 안내문을 ‘다름 — 둠’, ‘넣지 못함’으로 끝내는 것은 상태명처럼 줄여 쓴 내부 메모이므로 사용하지 않는다.

## 문체

- 한국어 안내는 ‘~합니다 / ~하세요’로 통일한다. ‘엉뚱한’, ‘진짜 폰트’, ‘하나짜리’, ‘있는 것’, ‘새 판’처럼 의미가 모호하거나 임의적인 표현을 피한다.
- 영어 안내는 sentence case와 완전한 문장을 기본으로 한다. `add it yourself`, `the fonts cannot be had`, `face(s)`처럼 거칠거나 부자연스러운 표현을 피한다.
- 긴 대시로 원인·결과·행동을 연결하지 않는다. 하나의 문장에 하나의 역할을 준다. `·`는 서로 나란한 짧은 수치·상태를 나열할 때만 쓴다.
- ‘파일을 넣다’는 파일 선택·저장·PDF 포함 중 어떤 동작인지 모호하다. 각각 ‘파일 선택’, ‘저장’, ‘PDF에 포함’으로 구분한다.
- 폰트명 같은 동적 문자열 뒤에 `이(가)`, `을(를)`을 붙이지 않는다. ‘{font} 폰트 파일을…’, ‘요청한 스타일: {style}’처럼 조사 처리가 필요 없는 문장으로 구성한다.
- 한글 조사 앞의 불필요한 공백을 제거한다. `Figma 는`, `PDF 에`, `.ttf 로` 대신 `Figma는`, `PDF에`, `.ttf로`라고 쓴다.
- 버튼 옆 문장을 ‘삭제한 뒤:’처럼 미완성으로 끝내지 않는다. 버튼이 줄바꿈되거나 사라져도 안내가 독립적으로 이해되어야 한다.
- 숫자 0·1·여러 개에서 영어 단복수와 동사 수 일치를 확인한다. 번역 함수는 사전의 기존 자리표시자 계약을 지킨다.

## 용어

| 개념 | 기본 표현 | 주의 |
| --- | --- | --- |
| Font file | 폰트 파일 | 설치되어 있는 폰트와 플러그인에서 사용할 파일을 구분 |
| Style | 스타일 | 굵기와 기울기를 모두 포함할 수 있으므로 무조건 ‘굵기’로 번역하지 않음 |
| Version/build | 버전 | ‘판’, ‘새 판’ 대신 사용. 실제로 확인한 버전에만 사용 |
| Embed | 폰트를 PDF에 포함 / 임베딩 | 일반 안내는 풀어 쓰고, 기능명·상태명은 임베딩 사용 가능 |
| Outline | 아웃라인 | 처음 설명할 때 모양은 유지되지만 검색·복사가 제한될 수 있음을 안내 |
| Static font | 정적(static) 폰트 | 실제 다운로드 폴더의 `static` 이름을 찾을 수 있게 병기 |
| Variable font | 가변 폰트 | ‘모든 굵기를 포함한다’고 단정하지 않음 |
| Collection face | 컬렉션에 포함된 스타일 | 일반 화면에는 `face`를 그대로 노출하지 않음 |
| Node | 레이어 | 개발용 상세 식별자는 필요한 경우 별도로 표시 |
| Merge | 병합 | ‘머지’ 사용하지 않음 |

## 사실과 상태의 정확성

1. **측정 결과와 추정을 구분한다.** 텍스트 폭이 다르다는 것은 확인할 수 있지만, 그 원인이 폰트 버전 차이라는 것은 별도 근거가 필요하다.
2. **동작이 끝나기 전에 완료라고 쓰지 않는다.** 파일 검증 메시지에 ‘저장했습니다’를 넣지 않는다. 저장 완료는 메인의 성공 응답을 기준으로 알린다.
3. **같은 사유가 사용되는 모든 위치를 확인한다.** 업로드 거절과 내보내기 제외에 공통으로 쓰는 문구에서 ‘아웃라인으로 내보냈습니다’처럼 이미 실행된 결과를 단정하지 않는다.
4. **오류를 유발하지 않은 행동을 예고하지 않는다.** 가변 폰트를 거절하거나 아웃라인으로 유지하는 경로에서 ‘다른 굵기로 내보냅니다’라고 단정하지 않는다. 파일의 기본 스타일과 필요한 파일을 안내한다.
5. **지원 범위를 잘못 축소하지 않는다.** TTF/OTF 외에 TTC/OTC도 받는 경로라면 파일 읽기 오류에서 TTF/OTF만 가능하다고 쓰지 않는다.
6. **확인하지 못한 것을 부재로 표현하지 않는다.** 일부 파일을 읽지 못했으면 ‘검사 미완료’로 표시한다.
7. **텍스트 목록의 근거를 정확히 쓴다.** `extractableText(collected)`로 만든 목록은 저장 PDF를 다시 파싱한 결과가 아니다. ‘파서가 읽을 내용’, ‘ATS가 읽는 결과’라고 표현하지 않는다.
8. **파일의 임베딩 설정과 법적 판단을 혼동하지 않는다.** ‘파일에 설정된 임베딩 제한’을 설명한다. 문구만으로 라이선스 전체를 검토한 것처럼 표현하지 않는다.

## 대표 변경 예시

### 폭 차이

이전: `{family} {style}: 글자 폭이 Figma와 {percent}% 다름 — 다른 판의 폰트라 원본 아웃라인을 둠`

변경: `{family} {style}: Figma와 텍스트 폭이 {percent}% 차이 납니다. 원본 모양을 유지하기 위해 아웃라인으로 내보냅니다.`

영어: `Text width for {family} {style} differs from Figma by {percent}%. The text will remain outlined to preserve its appearance.`

### 가변 폰트

이전: `굵기를 고를 수 없어 엉뚱한 굵기가 들어갑니다. 이 스타일 하나짜리(static) 파일을 올려 주세요.`

변경: `가변 폰트 파일은 지원하지 않습니다. 필요한 스타일의 정적(static) 폰트 파일을 선택하세요.`

영어: `Variable font files are not supported. Select a static font file for the required style.`

### 스타일 불일치

이전: `저장했습니다. 다만 이 파일은 {fileStyle} 굵기라…`

변경: `선택한 파일의 스타일은 {fileStyle}이며, 요청한 {slotStyle} 스타일과 다릅니다.`

저장 전 검증에서 사용되는 문구이므로 저장 완료를 알리지 않는다.

## 적용과 검토

이번 수정은 첨부된 폰트·제외 사유·오류 문구와 연결된 폰트 화면, 텍스트 확인, 일부 공통 안내에 적용했다. 모든 화면의 모든 문구에 대한 최종 검수가 끝났다는 의미는 아니다.

- 문구를 바꿀 때 사용 위치와 실제 분기 조건을 확인한다.
- 한국어와 영어를 함께 수정하고 자리표시자·단복수·상세 오류 표시를 확인한다.
- 문장을 줄이기 위해 필요한 사실을 없애지 않는다. 설명이 길면 UI에서 상세 정보를 분리한다.
- 사전 테스트 통과는 문체와 실제 화면 가독성 검수를 대체하지 않는다. 리디자인 적용 시 최소 폭·양 언어의 최종 렌더를 함께 확인한다.
