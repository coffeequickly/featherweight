## 1. 왜 바꾸는가

제품의 약속은 **PDF에 진짜 폰트를 넣는 것**이다. 그 하나가 두 문제를 동시에 푼다 —
텍스트가 살아 있고(검색·복사·ATS), 아웃라인 벡터보다 가벼워 파일이 작아진다.
이미지 다운스케일·목표 용량·하이퍼링크는 그 위에 얹힌 최적화다.

그런데 2.6.2의 화면은 이미지 압축 플러그인처럼 열린다. 메인 첫 요소가 이미지 프리셋이고
(`MainScreen.tsx:47`), 폰트는 체크리스트의 세 번째 줄이다.

구조상 문제는 넷이다.

| | 문제 | 근거 |
| --- | --- | --- |
| 1 | 체크리스트 네 줄 중 **둘은 경고를 낼 수 없다**. 검사가 아니라 영수증인데 같은 무게로 놓여 있다 | `PreFlight.tsx:81`·`101` — `tone: 'ok'` 고정 |
| 2 | **기타 설정(하이퍼링크·강제 아웃라인·대체 글자)이 메인에 없다.** 톱니 뒤에만 있다 | 체크리스트에 해당 줄 없음 |
| 3 | **폰트 문제와 텍스트 아웃라인이 두 줄로 갈려** 같은 사고를 두 번 경고한다 | `PreFlight.tsx:6` 주석이 그 중복과 싸우는 중 |
| 4 | **왕복 경로가 없다.** 결과 카드가 체크리스트 아래에 붙어, 고치고 다시 내보내려면 위로 스크롤 | `MainScreen.tsx:92` |

## 2. 사용자와 진입점

사용자는 둘이다.

1. 프리셋으로 확 뽑고 끝내는 쪽
2. 목적에 맞춰 세세하게 세팅해 뽑는 쪽

여기에 사용자가 고를 수 없는 두 번째 축이 겹친다 — **문제가 있는가 없는가**는 문서가 정한다.
1형 사용자도 폰트가 없으면 아웃라인으로 나간다. 그 사람은 고급 기능을 원한 게 아니라
사고를 수습해야 한다. (커뮤니티 댓글 "Issues with fonts not being found" 이 그 자리에서 나왔다.)

초기 퍼널은 셋이며 **배타적 모드가 아니라 진입점**이다. 어디로 들어와도 항목별 설정은
전부 살아 있고, 셋 다 같은 곳 — 추출 직전 상태 — 에 도착한다.

1. 자주 쓰는 세팅 (프리셋 = 상태)
2. 용량에 맞춰 시도 (목표 용량 = 동작)
3. 커스텀

## 3. 확정한 골격

| | 결정 |
| --- | --- |
| 창 | **440 × 560** (기존 400×560). `showUI({ width: 440, height: WINDOW_HEIGHT })` |
| 탭 | 시작 · 정렬 · 폰트 · 이미지 · 옵션 · 결과 |
| 탭 모양 | **라벨만**(아이콘 없음), 자연폭 왼쪽 정렬 |
| 선택 표시 | 검은 밑줄 + 굵게 |
| 문제 표시 | **앰버 글자 + 라벨 오른쪽 위 점**(absolute, 폭 0) |
| 비활성 | 정렬 탭은 조건 미충족 시 비활성. **사라지지 않는다** |
| 내보내기 | 푸터 고정, 어느 탭에서든. **톱니 제거** |
| 저장소 | 폰트 탭은 선택이 없어도 열린다 (저장소는 플러그인 단위 자산) |

탭 순서는 **워크플로우 순서**다. 시작에서 상태를 보고 → 정렬·폰트·이미지·옵션에서 고치고
→ 결과. 중요도 순이 아니다 — 중요도는 앰버 점이 알린다.

### 3.1 폭이 440인 근거 (실측, 시스템 UI 11px)

| 요소 | 필요 폭 (영어 기준) |
| --- | --- |
| 탭 여섯 (라벨만, 자연폭, 패딩 10) | 327px |
| 프리셋 타일 넷 (부제 9px, `aims for top quality` 84px) | **410px** ← 폭을 정하는 것 |
| 문제 카드 최장 문장 | 398px |

아이콘 + 라벨 탭은 고정폭에서 영어 498px가 필요해 520px를 요구했다. 아이콘을 빼면
탭이 폭을 결정하지 않는다. 부제를 10px → 9px로 낮추면 최소 410px, 여유를 두어 **440px**.

### 3.2 공통 시각 규칙

| 요소 | 기준 | 의도 |
| --- | --- | --- |
| 테두리 | **진짜 눌리는 것에만** | 값 칩·상태 표시는 테두리 없음. 가짜 버튼 제거 |
| 점선 | "값을 채워 넣는 자리" | 목표 용량 타일 |
| 파랑 `#0D99FF` | 선택됨 · 주 행동 | 상태색으로 쓰지 않음 |
| 앰버 `#E0A500` / `#7A5C00` | 문제 · 주의 | 색 하나에만 기대지 않는다(점·아이콘 병기) |
| 보라 | **쓰지 않음** | Figma에서 컴포넌트를 뜻하는 색이라 의미가 겹친다 |
| 아이콘 | 자리가 고정돼 학습되는 곳에만 | 값을 설명하는 데는 약하다 |
| 줄높이 | 본문 1.45~1.5 | 한글 상하 잘림 방지 (`--line-height-16: 18px`) |
| 간격 | 4·6·8·12·16 | 그룹 내부와 그룹 사이의 차이 |

## 4. 탭별 정의

### 4.1 시작

프리셋과 상태 요약을 함께 갖는다. **진단이 여기 있다** — 별도 진단 탭은 만들지 않는다.

```
프리셋 타일 넷 + 값 줄
─────────────────────
지금 상태
 ⚠ 문제 카드 (원인별, 갈 곳 표시)   → 해당 탭
 ✓ 정상은 회색 한 줄로 압축
─────────────────────
내보낼 페이지 썸네일
```

**프리셋 타일**

| 이름 | 부제 | 테두리 |
| --- | --- | --- |
| 선명하게 / Sharp | 인쇄·확대 / print & zoom | 실선 |
| 균형 / Balanced | 기본값 / default | 실선 |
| 최소 용량 / Smallest | 업로드 한도 / upload limits | 실선 |
| 목표 용량 / Target | 최적 품질에 도전 / aims for top quality | **점선** |

목표 용량만 점선인 이유: 셋은 **상태**(설정값 묶음)이고 목표 용량은 **동작**(조건을 만족하는
값을 찾아 주는 것)이다. 색은 쓰지 않는다 — 점선이 "종류가 다르다", 파랑이 "골랐다"를 맡아
역할이 겹치지 않는다. 부제 `최적 품질에 도전`은 실패할 수 있다는 사실을 담는다
(`FitOutcome`의 `unreachable`).

**값 줄** — `배율 1.5× 최대 변 1920px 품질 80%` + 우측 `이미지 ›`. 옅은 바탕으로 한 덩어리.
상태에 따라 세 모습:

| 상태 | 왼쪽 | 가운데 | 오른쪽 |
| --- | --- | --- | --- |
| 평소 | — | 값 셋 | `이미지 ›` |
| 직접 설정 | `직접 설정` | 값 셋 | `↺ 되돌리기` · `이미지 ›` |
| 목표 용량 | `파일 크기` | `− 5 +` `MB 이하` `자동` | `이미지 ›` |

**"직접 설정"에 이름을 준다.** 지금은 어느 타일도 안 켜지고 되돌리기 칩만 나타나 사용자가
"왜 아무것도 안 켜졌지"가 된다 (`PresetBar.tsx:67` 주석이 그 상태를 인정하고 있다).

**상태 영역** — 문제만 카드, 정상은 회색 한 줄. 카드는 **탭 단위로 묶어 최대 셋**
(폰트 문제 넷은 폰트 카드 하나로). 넷을 넘으면 마지막을 `외 N가지 · 상세 보기 ›`로 접는다.

정상 줄에는 링크를 달지 않는다 — 각 항목으로 가는 문은 탭이 이미 맡는다.

### 4.2 정렬

```
기준 [드롭다운] [⇅ 뒤집기]              N장 / ↺ 되돌리기
목록: 손잡이 · 번호 · 썸네일 · 이름 · 크기 · ×
─────────────────────
뺀 페이지 N장                      모두 되살리기
```

**정렬 기준을 넷으로 늘리고 방향을 분리한다.** 기준 × 뒤집기 = 여덟 조합이 두 컨트롤에 든다.

| 기준 | 구현 |
| --- | --- |
| 캔버스 위치 | 있음 (`sortByPosition`) |
| 이름 | 있음 (`sortByName`, 자연 정렬) |
| 레이어 순서 | 신규 — `parent.children` 인덱스 |
| 고른 순서 | 신규 — `selection` 배열 순서. **실기 확인 필요** (선택 순서가 유지되는지 미확인) |
| 직접 | 끌어 옮기면 이 상태가 되고 `되돌리기`가 나타난다 |

행을 끌면 순서 변경, 클릭하면 캔버스 점프(현재 동작 유지, `FrameList.tsx:84`).

### 4.3 폰트

목록은 훑어보는 곳, 상세는 손보는 곳으로 나눈다. **목록에 아이콘을 두지 않는다.**

```
⚠ 문제 배너 (상태에 따라 내용이 바뀜)     [폴더에서 찾기]
─────────────────────
이 문서가 쓰는 폰트                         9종
 Nexa                        1종 없음      ›
  [⚠Heavy] [Bold]
 Apple SD Gothic Neo    저장됨 · 2.6MB     ›
  [Regular] [Bold] [⚠SemiBold]
 Pretendard            내보낼 때 받아옴     ›
  [Regular] [Medium] [SemiBold] [Bold] 외 2개 스타일
─────────────────────
폰트 저장소            4.2 / 5 MB
[게이지]
이 문서에서 안 쓰는 폰트 2종 · 1.1MB    정리 ›
```

- **패밀리 한 줄 + 스타일 뱃지.** 9종이 아홉 줄이 아니라 세 줄. 문제 있는 뱃지만 ⚠와 앰버.
  폭이 모자라면 **정상 뱃지부터** `외 N개 스타일`로 접는다. 문제 뱃지는 접지 않는다.
- **저장소는 화면 아래 상시 고정.** 선택이 있든 없든 같은 자리. 게이지가 5MB 한도를 보여준다.
- **해결로 가는 길은 맨 위 배너.** 목록 아래가 아니다.
- **패밀리는 문서의 폰트 이름 그대로 나눈다.** `Pretendard`와 `Pretendard Variable`은
  **별도 두 줄**이다. 카탈로그가 둘 다 같은 static 인스턴스를 주더라도(`fontCatalog.ts:1256`)
  합치지 않는다 — 사용자가 Figma에서 고른 이름이 화면에 없으면 "내가 고른 게 왜 없지"가 된다.
  실제로 받아오는 것은 상세 화면이 말한다(`Pretendard 1.3.9 · jsDelivr`).

  참고: 가변 폰트는 **사용자가 넣는 파일만** 거절한다(`fontFile.ts:39`, `axes.length > 0`).
  카탈로그는 `… Variable` 이름을 알아보고 static 인스턴스를 내려받으므로,
  `Pretendard Variable Regular · 내보낼 때 받아옴`은 모순이 아니라 의도된 동작이다.

- **스캔 결과 상자를 없앤다.** 배너가 상태에 따라 내용을 바꾼다 — 스캔 전 `1종을 찾지
  못했습니다 [폴더에서 찾기]`, 스캔 후 `9종 저장 · 3종은 공간이 모자랍니다 [공간 비우기]`.
  문제가 풀리면 저절로 사라지므로 닫기 버튼이 필요 없다.

**패밀리 상세 (한 뎁스)** — 탭 바는 유지되고 `‹ Nexa   이 문서에서 2종` 헤더가 붙는다.
스타일마다 카드 하나:

```
Heavy                              파일이 필요합니다
 이 문서의 텍스트 3개가 씁니다               ← 얼마나 중요한지
 폴더를 훑었지만 이 스타일이 없었습니다        ← 왜 실패했는지
 선택하지 않으면 아웃라인으로 내보냅니다        ← 안 고치면 어떻게 되는지
 [파일 넣기] [폴더에서 다시 찾기]

Bold                               저장됨 · 1.6MB
 Nexa-Bold.otf · 버전 1.002 · 2026-09-08 넣음
 이 문서의 텍스트 12개가 씁니다
 [바꾸기] [지우기]
```

자동으로 받아오는 패밀리는 출처·라이선스·네트워크 필요·다른 버전 존재를 말한다.

```
Regular                            내보낼 때 받아옴
 Pretendard 1.3.9 · jsDelivr · SIL OFL
 내보낼 때 인터넷 연결이 필요합니다
 같은 이름의 다른 버전이 2개 있습니다
 [버전 고르기] [내 파일로 대신하기]
```

저장소 줄은 문맥에 맞게 말한다 — 상세에서는 `이 스타일을 저장하려면 약 1.4MB가 필요합니다`.
동적 폰트명 뒤에 조사를 붙이지 않는다(10.1-4).

**없어지는 것**: `⋯` 메뉴, 교체 버튼(= `＋`로 덮어쓰기), 다시 넣기 버튼, 스캔 결과 상자와
그 닫기 버튼, 행마다 붙던 아이콘 두세 개.

### 4.4 이미지

```
[프리셋 상태 줄]
해상도
[1×] [1.5×] [2×] [3×] [4×]
1.5× · 150%까지 확대해도 선명합니다 · 108 DPI
가장 크게 놓인 이미지가 1263px 이 됩니다 · 작게 놓인 것은 그만큼만
─────────────────────
화질
JPEG [조절바 50–100%] 80%
[✓] 투명하지 않은 PNG 도 JPEG 로 바꾸기
─────────────────────
이 문서의 이미지        10장 중 5장이 줄어듭니다
 표지 배경     3024px → 1263
 제품 사진 01  2400px → 1263
 로고           512px   그대로
```

**배율의 기준은 그 이미지가 캔버스에서 차지하는 크기**다. 프레임이 아니다.
`targetFor = min(상한, max(보이는 긴 변 × 배율, 640))`, 보이는 긴 변은
`node.width × 부모 확대·축소 배율` (`images.ts:130`). 절대 확대하지 않는다
(`scaledSize:153`).

**컨트롤을 셋으로 줄인다.**

| 없앨 것 | 이유 |
| --- | --- |
| 최소 변 (640/1024/1600) | `MIN_TARGET_LONG_EDGE = 640`과 `KEEP_BYTES_FLOOR = 100_000`이 이미 지킨다. 아래 목록의 `그대로` 줄이 그 사실을 보여준다 |
| 최대 변 (HD/FHD/QHD/4K) | 아래 참조 |
| 해상도 비교 그림 | 최대 변을 견주려고 있던 것 |

**최대 변을 사용자 컨트롤에서 빼는 근거** — 상한은 고른 배율을 조용히 덮어쓴다.
지금 프리셋에서 이미 벌어지는 일:

| 프리셋 | A4 842pt | 슬라이드 1920pt |
| --- | --- | --- |
| 최소 용량 (1× · 1280) | 842px → 72 DPI | 1920 → **1280으로 잘림** → 48 DPI |
| 균형 (1.5× · 1920) | 1263px → 108 DPI | 2880 → **1920으로 잘림** → 72 DPI |
| 선명하게 (2× · 3840) | 1684px → 144 DPI | 3840 → 딱 걸림 → 144 DPI |

같은 프리셋인데 문서 종류에 따라 화질이 다르고, 어디에도 적혀 있지 않다. 상한이 진짜
필요한 경우는 거대 프레임 하나뿐이며(5000pt 보드 × 4× = 20,833px, 캔버스 최대 변 초과)
그건 사용자가 판단할 문제가 아니다. **4096px 하드코딩**이면 4× × A4(3508)는 통과하고
비정상 크기만 막는다.

**대가**: 슬라이드에서 균형 프리셋이 1920 → 2880px가 되어 파일이 커진다(면적 2.25배).
**프리셋 값 재조정이 필요하며 실측 대상이다.** 이 문서는 UI만 정의한다.

**배율 라벨을 DPI가 아니라 `×`로 쓰는 이유** — Figma 내보내기가 `@1x @2x @3x`를 쓰므로
같은 어휘다. 뜻은 설명 줄이 준다(`150%까지 확대해도 선명합니다`). DPI는 그 줄 끝에
남겨 인쇄 요구("300 DPI로 주세요")도 받는다. 3×·4×를 새로 넣는다 — 지금 천장 2×(144 DPI)는
`인쇄·확대`라는 프리셋 부제에 못 미친다.

**타입 변경 필요**: `Settings['multiplier']`가 `1 | 1.5 | 2` 유니온이다. 3·4를 넣으려면
넓혀야 하고, 옛 저장값 이관은 `nearest()`가 이미 한다.

**화질은 조절바다** — 지금도 그렇다(`RangeSlider` min 0.5 / max 1 / increment 0.05).
목표 용량이 0.04 단위로 찾은 값(예 84%)을 세그먼트로는 표시할 수 없다.
**목표 용량일 때 화질 섹션을 감추지 않는다** — 지금은 통째로 사라져
(`SettingsPanel.tsx:113`) 어떤 화질로 나가는지 알 수 없다. 잠그고 찾아낸 값에 핸들을 놓는다.

### 4.5 옵션

```
텍스트
 [✓] 하이퍼링크 유지
 [✓] 폰트에 없는 글자는 대체 폰트로 그리기
─────────────────────
주의해서 쓸 것
 ┌──────────────────────────────────────┐
 │ [ ] 모든 텍스트를 아웃라인으로 내보내기 │
 │  켜지면: 지금 폰트 탭의 설정은 쓰이지    │
 │  않습니다. 9종 모두 아웃라인으로 나갑니다 │
 └──────────────────────────────────────┘
─────────────────────
[설정을 기본값으로]              Featherweight x.y.z
```

`모든 텍스트를 아웃라인으로`는 제품의 핵심 기능을 끄는 것이라 상자에 따로 두고, 체크박스
색도 파랑이 아니라 앰버다 — "잘 설정된 상태"가 아니라 "특수한 상태"라는 뜻. 켜면 상자가
앰버가 되고 **다른 탭에 미치는 영향을 그 자리에서 말한다.**

톱니를 없앴으므로 설정 초기화가 여기로 온다. 이 탭이 비어 보이는 것은 괜찮다 —
옵션이 셋뿐인 게 좋은 신호다.

### 4.6 결과

내보내기 전에는 빈 상태, 내보낸 뒤에는 결과.

```
✓ 이력서.pdf
  842KB · 3쪽 · 4.2초
  ✓ 목표 5MB 안에 들었습니다
─────────────────────
텍스트                          142개 모두 포함
 대체 글자 2자. Pretendard에 없어 Inter로 그렸습니다.  [※] [얇은 공백]
─────────────────────
이미지                        10장 중 5장 줄임
 PDF 안 이미지 612KB · 아웃라인 벡터 0
─────────────────────
임베드한 텍스트                        전체 보기 ›
 ┌──────────────────────────────┐
 │ 홍길동                        │
 │ 프로덕트 디자이너 · ...        │
 └──────────────────────────────┘
```

- 목표 용량을 못 맞췄으면 **최선값을 말한다** — `여기가 최소입니다`. 목표를 다시 잡을
  근거가 그 숫자다.
- **임베드한 텍스트를 인라인으로 몇 줄 보여준다.** 지금은 별도 화면으로 들어가야 한다.
  이 제품을 쓰는 이유가 결과 화면에서 눈으로 확인된다.
- 버튼이 `다시 내보내기`로 바뀐다. 고치고 다시 뽑는 게 주 경로다.

**명명 주의** — `extractableText`는 우리가 임베드한 텍스트를 모은 것이지, 생성된 PDF를
다시 파싱한 결과가 아니다(`useExport.ts:77`). 따라서 `파서가 읽는 내용`이 아니라
**`임베드한 텍스트`**로 쓴다. ATS 통과나 실제 복사 결과를 보장하는 문구를 쓰지 않는다.

## 5. 하위 페이지

탭 바는 유지되고 그 아래 `‹ 제목` 헤더가 붙는다. 뒤로 가면 원래 탭으로 돌아가고,
진입 지점에 포커스가 복귀한다.

| 페이지 | 여는 곳 |
| --- | --- |
| 폰트 패밀리 상세 | 폰트 탭의 패밀리 줄 |
| 아웃라인 상세 | 시작 탭의 텍스트 문제 카드 |
| 임베드한 텍스트 전체 | 결과 탭의 `전체 보기 ›` |
| 저장소 정리 | 폰트 탭의 `정리 ›` |

### 아웃라인 상세

사유가 묶는 단위다. 레이어를 나열하지 않고 원인별로 그룹을 만든다.

```
‹ 아웃라인으로 나가는 텍스트                    15개
┌ 폰트가 없어서                    12개  폰트 탭 › ┐
│ Nexa Heavy · Pretendard SemiBold —              │
│ 이 폰트 파일을 선택하면 PDF에 포함합니다          │
│  채용 공고 제목      Nexa Heavy 32     보기 ›    │
│  … 외 9개                                       │
└─────────────────────────────────────────────────┘
┌ 글자에 선이 있어서                 2개           ┐
│ PDF는 글자에 선을 포함할 수 없습니다.              │
│ 선을 제거하면 폰트를 포함해 내보냅니다             │
│  HEADLINE           선 2px          보기 ›       │
└─────────────────────────────────────────────────┘
```

이동 컴포넌트가 둘이다.

| | 언제 | 무게 |
| --- | --- | --- |
| 그룹 단위 `폰트 탭 ›` | 원인이 폰트인 그룹만 | 파랑·굵게 — **실제 해결 경로** |
| 레이어 단위 `보기 ›` | 모든 행 | 회색 — 캔버스 점프 |

선·효과 그룹은 플러그인이 못 고치므로 갈 탭이 없다. 대신 **뭘 하면 되는지**를 말한다.

## 6. 푸터

버튼은 어느 탭에서든 아래에 고정. 상태에 따라 여섯 모습.

| 상태 | 모습 |
| --- | --- |
| 평소 | 버튼만 |
| 문제 있음 | 버튼 위에 경고 한 줄 + 갈 곳. **평소에는 넣지 않는다**(모든 탭에서 세로 24px 손해) |
| 선택 없음 | 버튼 비활성 |
| 내보내는 중 | `이미지 줄이는 중 · 7 / 10` + 취소 + 막대 |
| 목표 용량 탐색 중 | `후보 재는 중 · 3 / 5 · 지금 4.1MB` + 취소 + 막대 |
| 실패 | 어두운 토스트(`다시 시도` 포함)를 띄우고 **버튼·진행 상태는 즉시 원래대로** |

토스트가 사라지면 오류 원문이 없어지므로, **원문은 결과 탭에 실패 기록으로 남긴다.**
그래야 결과 탭이 "마지막에 무슨 일이 있었나"를 항상 갖는다.

### 7.2 발견 — 쓰지 않는 표준 14 폰트가 번들의 22%다

`@pdf-lib/standard-fonts`(127KB)와 그것을 푸는 `brotli`(88KB)를 합쳐 **215KB / 22.4%**다.
이 플러그인은 진짜 폰트를 임베드하므로 표준 14 폰트(Helvetica·Times·Courier)를 쓰지 않는다.

확인한 것:

- `src/` 전체에 `StandardFonts`·`embedStandardFont` 호출이 없다
- 폰트 임베드 경로는 `document.embedFont(bytes, …)` 하나뿐 (`textLayer.ts:112`)
- 폼 필드·외형 생성(`getForm`·`TextField`) 경로를 쓰지 않는다
- pdf-lib 안에서 이 패키지를 import 하는 곳은 둘이다
  - `core/embedders/StandardFontEmbedder.js` — 표준 폰트를 임베드할 때만 실행
  - `utils/objects.js` — `FontNames` 열거값 하나만 쓴다 (`StandardFontValues = values(FontNames)`)

따라서 **`FontNames`·`Encodings`·`Font`만 갖는 스텁으로 별칭 처리하면 215KB가 빠진다.**
다만 pdf-lib 내부에 우리가 추적하지 못한 폴백 경로가 있을 수 있으므로 7.5의 검증을 거친다.

### 7.3 이번 리디자인이 새로 만드는 비용

**썸네일 — 시작 탭에 넣으면 비용이 늘어난다.** 지금은 정렬 화면을 열 때만 요청한다
(`App.tsx:111`). 시작 탭에 두면 선택이 있는 채로 열 때마다, 그리고 선택을 바꿀 때마다
프레임 수만큼 `exportAsync`가 돈다. 코드 주석이 그 무게를 말한다 — *"30장을 하나씩
기다리면 몇 초가 걸리던 일"* (`selection.ts:287`). 지금은 `THUMB_CONCURRENCY = 6`,
`THUMB_LONG_EDGE = 160`으로 완화돼 있다.

→ **시작 탭에서는 앞의 3~4장만 그리고 나머지는 `+N`으로 표시한다.** 시작 탭의 목적은
"무엇을 뽑는지 확인"이라 전부 필요하지 않고, 비용이 대략 1/8로 준다. 전체 목록은 정렬 탭이 맡는다.

**이미지 목록 — 원본 픽셀을 읽는 비용.** 4.4의 목록(`표지 배경 3024px → 1263`)은 이미지마다
원본 크기가 필요하다. 읽는 경로가 둘인데 한쪽이 비싸다 — *"파일 머리에서 먼저, 안 되면
Figma에 묻는다. 그건 통째로 디코드라 느리다"* (`imageSize.ts:54`).

→ `preflight`가 이미 같은 값을 모으고 있으므로(`Preflight.images`·`sizing`) **재사용을 먼저
확인한다.** 재사용할 수 없으면 목록을 기본 접힘으로 두고 펼칠 때 읽는다.

### 7.4 손대지 않을 것

| 항목 | 지금 | 이유 |
| --- | --- | --- |
| 프레임 내보내기 동시성 | 1 (순차) | *"빠르게 만들려다 메모리로 죽는 쪽이 더 비싸다"* (`main.ts:229`). 의도된 선택 |
| 목표 용량의 실제 export 2회 | 기준 1회 + 최종 1회 | 고정분을 알아내려면 실제 PDF가 한 번 필요하다. 대신 진행 문구로 단계를 보여준다(6절) |

### 7.5 우선순위와 검증 절차

프로덕션 플러그인이므로 **이득이 큰 것부터, 검증 가능한 것만** 손댄다.

| 순위 | 작업 | 이득 | 위험 | 검증 |
| --- | --- | --- | --- | --- |
| 1 | 시작 탭 썸네일을 3~4장으로 제한 | 여는 속도 | 없음 (설계 단계에서 회피) | 눈으로 |
| 2 | 이미지 목록에 `preflight` 데이터 재사용 | 추가 디코드 0 | 없음 | 데이터 경로 확인 |
| 3 | `@pdf-lib/standard-fonts` 스텁 | **번들 −215KB (−22%)** | **중간** — 추적 못 한 폴백 경로 | 아래 |
| — | 번들 코드 스플리팅 | 큼 | 높음 (빌드 개편) | 이번엔 안 함 |

**3번의 검증 절차** — 이 순서를 다 통과하지 못하면 되돌린다.

1. 스텁을 넣고 `npm test`(467개) + `CATALOG_NET=1`(641개) 전부 통과
2. `PIPELINE_PDF_OUT`으로 실제 PDF를 뽑아 `tools/compare-pdf.py`로 스텁 전후를 비교 —
   페이지 수·글리프·이미지 바이트가 같아야 한다
3. 한글·라틴이 섞인 문서, 아웃라인 폴백이 있는 문서, 하이퍼링크가 있는 문서 각각으로 실기 확인
4. 스텁의 `Font`는 조용히 넘어가지 않고 **던지게** 만든다 — 예상 못 한 경로가 있으면
   테스트에서 드러나야지 런타임에 이상한 PDF가 나오면 안 된다

3번은 UI 리디자인과 독립적이므로 **별도 커밋·별도 릴리즈로 분리한다.** 리디자인과 섞으면
문제가 생겼을 때 원인을 가릴 수 없다.

### 10.1 시안 문구는 예시일 뿐이다

4~6절의 화면 그림에 적힌 한국어는 **배치를 보려고 쓴 임시 문구**다. 실제 문구는
[UI 문구·번역 작성 기준](UI-COPY-GUIDE.md)에 맞춰 다시 쓴다. 시안을 그대로 옮기면 안 된다.

시안이 그 기준을 어기는 지점을 미리 정리한다. 구현할 때 이 목록을 체크리스트로 쓴다.

| | 기준 | 시안의 위반 | 고칠 방향 |
| --- | --- | --- | --- |
| 1 | `진짜 폰트`를 쓰지 않는다 | `9종 모두 진짜 폰트로 나갑니다`, `142개 전부 진짜 폰트로`, `선을 빼면 진짜 폰트로 나갑니다` | **`PDF에 포함`으로 (10.2 결정)** |
| 2 | `·`는 나란한 짧은 수치·상태 나열에만 | `Nexa Heavy · 나머지 4종은 자동으로 받아옵니다`, `1.5× · 150%까지 확대해도 선명합니다 · 108 DPI`, `내보내기에 실패했습니다 · 이미지를 읽지 못했습니다` | 문장은 문장으로 끊는다 |
| 3 | 한글 조사 앞 공백 제거 | `PDF 는`, `1263px 이`, `Pretendard 에`, `PNG 도`, `JPEG 로`, `목표 1MB 를` | 붙여 쓴다 |
| 4 | 동적 문자열 뒤에 조사를 붙이지 않는다 | `Nexa Heavy 를 넣으려면 약 1.4MB가 필요합니다` | `이 스타일을 저장하려면 약 1.4MB가 필요합니다` |
| 5 | `넣다`는 파일 선택·저장·PDF 포함 중 무엇인지 모호 | 버튼 `파일 넣기`, `Nexa-Bold.otf … 2026-09-08 넣음`, `넣지 않으면 아웃라인으로 나갑니다` | `폰트 파일 선택` / `2026-09-08 저장` / `폰트 파일을 선택하지 않으면…` |
| 6 | 상태명은 짧은 명사구, 마침표 생략 | `파일이 필요합니다`(상태 자리), 그룹 제목 `폰트가 없어서`·`글자에 선이 있어서` | `폰트 파일 필요`, `폰트 없음`, `글자에 선 있음` |
| 7 | 긴 대시로 원인·결과·행동을 잇지 않는다 | `목표 1MB를 못 맞췄습니다 — 여기가 최소입니다`, 영문 `1 font missing — 3 text layers will be outlined` | 두 문장으로 |
| 8 | 끝나기 전에 완료라고 쓰지 않는다 | 목록의 `자동으로 받아옴` (아직 받지 않았다) | `내보낼 때 받아옴` — 상세 화면과 문구를 맞춘다 |
| 9 | `extractableText` 목록의 근거 | `파서가 읽는 내용` | `임베딩한 텍스트` (4.6에 반영 완료) |
| 10 | 버튼은 실행할 동작을 구체적으로 | `폴더에서 찾기`, `정리`, `바꾸기`, `내 파일로 대신하기` | `폰트 폴더 선택`, `저장 공간 관리`, `다른 파일 선택`, `내 폰트 파일 선택` |
| 11 | 거친 구어를 피한다 | `폴더를 훑었지만`, `못 넣습니다`, `그림으로 나갑니다`, 괄호 안 `만 있음` | `폴더를 검사했지만`, `포함할 수 없습니다`, `이미지로 내보냅니다`, 완전한 문장 |

### 10.2 `진짜 폰트`의 대체 — 결정: `PDF에 포함`

가장 많이 걸리는 표현이다. 이 제품의 핵심 약속을 말하는 자리라 대체어를 정해야 한다.
후보 셋:

**결정: 기능으로 말한다 — `PDF에 포함`.** 사용자가 이 플러그인을 찾은 이유가 곧
"폰트를 PDF에 포함"이다. 검색·복사는 그래서 따라오는 이득이지 목적이 아니므로,
화면은 목적을 말한다.

| 자리 | 쓰지 않는다 | 쓴다 |
| --- | --- | --- |
| 시작 탭 요약 | `9종 모두 진짜 폰트로 나갑니다` | `폰트 9종을 모두 PDF에 포함합니다` |
| 시작 탭 빈 상태 | `텍스트는 진짜 폰트로 넣습니다` | `텍스트는 폰트를 포함해 내보냅니다` |
| 폰트 상세 | `이 폰트를 넣으면 진짜 폰트로 나갑니다` | `이 폰트 파일을 선택하면 PDF에 포함합니다` |
| 아웃라인 상세 | `선을 빼면 진짜 폰트로 나갑니다` | `선을 제거하면 폰트를 포함해 내보냅니다` |
| 결과 탭 상태 | `142개 전부 진짜 폰트로` | `142개 모두 포함` |
| 결과 탭 부분 | `142개 중 138개가 진짜 폰트로` | `142개 중 138개 포함` |

대비되는 쪽은 `아웃라인으로 내보냅니다`로 통일한다. `나갑니다`는 구어라 쓰지 않는다.

영어는 `embedded`를 쓴다 — `9 fonts embedded`, `138 of 142 embedded`,
`3 text layers will be outlined`. `real fonts`는 README·커뮤니티 설명 등
마케팅 문구에서만 유지하고 UI 안에서는 쓰지 않는다.
