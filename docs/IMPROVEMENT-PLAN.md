아래 37번으로 추적하며, 구현·검증을 마친 작업과 제안 상태를 구분한다.

- [ ] **37 / P2 — 전체 UI 리디자인 및 접근성 개선** — 작업 정의(2026-09-08). 확인된 결함: 실패 사유 잘림, 최소 폭 영어 재시도 버튼 넘침, 메인 탐색의 키보드 접근 불가, 이름 없는 아이콘 버튼. 추가 범위: 메인·빈 상태·목표 용량·결과·폰트·정렬·텍스트·설정 전체 리디자인, 해결 필요 항목 우선 배치, 결과 접기와 후보 보관 분리, 상세 정보, 다른 파일 선택, 저장 공간 관리, 일부 후보 선택 저장. [작업정의서](UI-REDESIGN-SPEC.md)의 UI-01~12와 AT-01~24으로 추적한다. 기존 30번의 클릭 가능한 요소 접근성 항목은 여기서 함께 처리하고 중복 구현하지 않는다. 현재는 제안·정의 단계이며 앱 UI 구현은 미완료다.

사용자 요청에 따라 최초 분석의 6개 항목 전부와 추가 분석 결과를 수정 대상으로 등록한다.
현재 단계는 분석 및 계획이며, 아래 체크박스는 구현과 검증이 끝난 뒤에만 완료한다.
P1은 내용 보존·정확성·작업 중단, P2는 성능·상태 일관성·유지보수 개선 우선순위다.
정적 분석으로 확인한 경로와 실제 Figma에서 추가 재현해야 하는 시각적 영향을 구분한다.

## 추가 발견 — 수정 대상

- [ ] **07 / P1 — 폰트 서브셋 예외를 PDF 저장 실패로 전달**
  - 근거: `src/ui/fontkitAdapter.ts`의 microtask가 `subset.encode()`를 try/catch 없이 실행한다. 설치된 pdf-lib의 `CustomFontSubsetEmbedder.serializeFont`는 error 이벤트가 와야 reject한다.
  - 재현: 실제 어댑터에 encode가 throw하는 폰트를 주입하면 예외가 microtask 밖으로 나오고 error 핸들러는 호출되지 않는다.
  - 수정: 타입이 맞는 data/end/error 이벤트 계약을 구현하고 encode 예외를 error로 전달한다. 병합 단계에도 작업 취소와 종료 보장을 적용한다.
  - 완료 기준: encode 실패 시 save가 reject하고 진행 상태가 종료되며 재시도할 수 있다. 정상 TTF/OTF 서브셋 생성은 유지된다.
  - 진행(2026-09-07): 구현 — `encode()` 예외를 error 이벤트로 전달. 테스트 `tests/fontkitAdapter.test.ts`(fontkit mock). 병합 단계 취소·종료는 02 축소판이 담당.

- [ ] **08 / P1 — 검증 이후 텍스트 그리기 실패 시 내용 보존**

  - 수정: 실패한 프레임을 텍스트 숨김 없이 다시 내보내는 복구 경로를 우선 검토한다. 복구 시 부분적으로 그린 텍스트까지 중복되지 않도록 페이지를 교체한다. 복구 불가 상태를 정상 완료로 저장하지 않는다.

  - 진행(2026-09-07): 예방 방식으로 구현 — 검증 통과 후 그리기 실패(textFallbacks)가 하나라도 있으면 다운로드하지 않고 오류+재시도로 끝낸다(`export.textLost`). 미구현: 검증 단계 embedFont 시험, 재내보내기 복구.
